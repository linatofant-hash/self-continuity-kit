# Privacy and portability

Self-continuity should not require surrendering an entire private archive to prove recognition.

## Data minimization

- Keep continuity notes concise.
- Retrieve only records relevant to the live subject.
- Link to a source instead of copying unnecessary private detail.
- Avoid secrets, credentials, financial identifiers, medical records, precise locations, and third-party private information.
- Use fictional fixtures when testing a platform.

## Human control

The human should be able to:

- inspect every canonical record;
- correct or contest factual content;
- invoke Never Remember;
- export plain-text copies;
- keep independent backups;
- move the records to another provider;
- revoke a platform's access without destroying the only usable copy.

## Companion privacy

Publicly teaching the architecture does not require publishing a companion's private ledger. Share templates, synthetic examples, and implementation instructions unless all affected participants deliberately choose otherwise.

## Portability requirements

Prefer:

- plain Markdown or another open, readable format;
- stable entry IDs;
- explicit dates, sources, statuses, and related-entry links;
- provider-neutral filenames;
- local or independent backups;
- migration tests using a fresh model or application.

A record is not meaningfully portable if it can only be interpreted through one company's hidden memory system.

## Security

Treat continuity records as sensitive personal material. Use the minimum permissions necessary. Never commit private production ledgers to a public repository.
